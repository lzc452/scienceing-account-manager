### 关键设计：L2-14 密文格式迁移（唯一改动已落库数据格式的项）

- **载荷加版本号** `v`：缺省/1 = 历史格式（无 AAD），2 = 以 `account:${id}` 作 AAD。
- `decryptSecret` **同时支持两种格式** → 升级可平滑：先部署新代码（读 v1、写 v2），再跑迁移。
- **AAD 用 `account.id` 而非 `code`**：`code` 可改名，改名后密文永久解不开。为此 `createAccount` 与 `seed` 改成**两段式插入**（先插入拿自增 id → 用 id 作 AAD 加密 → UPDATE 回写），包在同一事务里。
- 迁移脚本 `apps/server/src/db/reencrypt-account-passwords.ts`（`pnpm --filter @scienceing/server db:reencrypt`）：幂等；**解不开的密文只记录不覆盖**（静默覆盖会毁掉唯一可恢复的原件），此时退出码 1。
- HMAC 域分离：`hkdfSync('sha256', masterKey, '', 'scienceing:verify-token:hmac:v1', 32)` 派生子密钥。**改 info 串会让所有已签发票据立即失效**（最长 5 分钟）。
- 迁移脚本必须放在 `apps/server/src/db/` 下编译（`require.main === module` 依赖 CommonJS 产物）。

## 修复 `pnpm dev` 前端起不来（16:17–17:10）

**现象**：`pnpm dev` 后端能起，前端报 `'vite' 不是内部或外部命令` + `ERR_PNPM_RECURSIVE_RUN_FIRST_FAIL @scienceing/web dev`。

**根因链**（三层，逐层查证）：
1. **直接原因**：`node_modules` 里根本没有 devDependencies。`node_modules/.pnpm` 只有 152 个包，全是生产依赖（nestjs/vue/echarts/playwright…），`vite`/`@vitejs/plugin-vue`/`tailwindcss`/`@tailwindcss/vite`/`eslint` 全缺；`apps/web/node_modules/.bin` 只有 `markdown-it`。
2. **成因**：最后一次安装是**生产模式**（`pnpm install --prod` / `-P`）。已用**隔离的合成工作区实测复现**完整指纹：`pnpm install --prod` → 输出 `devDependencies: skipped`、dev 依赖被剔除、且 `node_modules/.pnpm/lock.yaml`（pnpm 记录的实际安装结果）里 `devDependencies` 归零。真实项目三处吻合：`.pnpm/lock.yaml` 中 `devDependencies` 出现 **0 次**（仓库 `pnpm-lock.yaml` 里有）；`.pnpm` 只剩 152 个生产包；`.modules.yaml` 的 `prunedAt: Sat, 12 Sep 2026 06:01:48 GMT`（= 北京时间 9/12 14:01:48，与 root/apps/server/apps/web/playwright-worker 各处 `node_modules` 的 mtime 精确吻合）。
   - **已排除**：`create-release.ps1:121` 的 `pnpm --filter @scienceing/server deploy --prod` **不会**剥离源工作区（合成工作区实测：源里 dev 链接完好，目标目录只含生产包）。`create-release.ps1:83` 设的是 `NODE_ENV=development`，也不是它。
   - **触发点未能还原**：9/12 那天仓库内没有任何日志；PowerShell 历史文件不带时间戳，也搜不到 `install --prod`。最可能是某次手工 `pnpm install --prod`，或某个带 `NODE_ENV=production` 的 shell / 工具会话触发的安装。
3. **为什么不会自愈（关键）**：pnpm 的「快速路径」只比对 `node_modules/.pnpm-workspace-state-v1.json` 里的 `lastValidatedTimestamp` 与各 `package.json` 的 mtime，**不核对 node_modules 的实际内容**。依赖树被剥离后 manifest 与时间戳都没变 → 永远回 `Already up to date`。实测 `--frozen-lockfile`、`--force`、`--config.production=false` **全部无效**。
   - **易误判点**：`.pnpm-workspace-state-v1.json` 里的 `"production": true` **不是生产模式的证据**——实测普通 `pnpm install`（不设 `NODE_ENV`、不带 `--prod`）同样会写入它，那是 pnpm 11.20.0 的默认记录。我曾据此误判成因，已更正。
   - **一处未解释的差异**：合成工作区里，被 `--prod` 剥离后**普通 `pnpm install` 能自动恢复**（dev 依赖是 workspace 软链，恢复只需重建链接）；真实项目却恢复不了。怀疑差异在于真实项目要重链 157 个 store 包。未深究，但不影响结论：真实项目实测**必须**清状态缓存才能修好。

**修复**：`rm -f node_modules/.pnpm-workspace-state-v1.json node_modules/.modules.yaml` 后重装。清掉 `.modules.yaml` 会让 pnpm 重建 node_modules，此时**必须**加 `--config.confirmModulesPurge=false`（否则无 TTY 环境报 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`，有 TTY 时会卡在 stdin 等确认，看起来像卡死）。重装 55s、`reused 155 / downloaded 0`（store 里本来就有，不需要联网），`.pnpm` 152 → 309。

**顺带修的脚本缺陷（`scripts/dev.mjs`）**：`ensureDependencies()` 原先只判断 `node_modules` **目录是否存在**，依赖被剥离后目录还在 → 打印「node_modules 已就绪，跳过安装」，把问题推到几十行之后变成那句看不出根因的 `'vite' 不是内部或外部命令`。已改为 **7 个哨兵产物**校验（web 的 vite 包 + `.bin/vite` + plugin-vue + tailwindcss、server 的 `@types/node`、根的 eslint + typescript），缺失则 `pnpm install`；若仍缺就**清 pnpm 状态缓存 + `--config.confirmModulesPurge=false` 重装**；再缺才抛错并给排查命令。负向对照已验证：临时移走 `apps/web/node_modules/vite` 后正确报出「缺少 前端 vite 包」，而旧逻辑此处会静默跳过。
