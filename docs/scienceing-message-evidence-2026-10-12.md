- 分类包含“全部消息”“AI服务消息”“系统消息”“应助消息”；截图选中“全部消息”，没有展示“应助消息”分类的内容。
- 当前展开条目为“服务器迁移升级完成通知”，属于服务公告内容，不能据此识别 SCIHelp 申请完成。
- 消息按日期展示，条目可见标题、正文、时间及红点。截图未提供稳定消息 ID、分类值、关联任务 ID 或结果跳转地址。
- 底部可见当前页 `1` 与上一页／下一页控件；总页数、每页数量、筛选后的分页方式尚未取得。
- 页面有“一键清空”“全部已读”控件，顶部铃铛带数字角标。控件和角标的实际接口行为尚未验证。
- 账号邮箱显示在顶部右侧；实际邮箱、消息正文及原始截图不提交到仓库。

服务公告提到 API 开放平台上线，但没有提供订阅或求助结果接口的契约，不能据此认定已找到采集 API。

## 对第二期采集的影响

“应助消息”是 SCIHelp 结果通知的候选来源，这一对应关系仍需真实任务消息及关联结果验证。现有证据不足以确定它是否包含处理中、完成、失败消息，或是否每次完成均产生消息。

如果选用消息中心，必须依据已核实的类型及关联任务识别本期结果；系统公告和 AI 服务消息不作为订阅或 SCIHelp 结果同步。仅保存事件所需标识、时间、状态、简要标题及可信结果入口，不同步完整消息正文。

去重应依据稳定消息／任务／结果标识，不能依赖红点、铃铛数字或上游已读状态。账号平台用户各自的已读状态与科应共享账号的已读状态独立；其他使用者阅读科应消息不应造成漏通知或重复通知。

采集路径不得执行“一键清空”或“全部已读”。需核实列表读取、分类切换及展开正文是否会改变上游已读状态，再确定可用的只读路径。若同时从求助记录和消息中心发现同一完成任务，须按已验证的关联标识去重，不为同一结果生成两次通知。

## 下一步最小材料

1. 消息中心选中“应助消息”后的截图，保留已有条目、日期、时间、状态、结果链接及分页；没有消息时提供空状态即可，不要求新提交申请。
2. 有已有完成消息时，补充其对应求助记录及实际结果入口，核对任务与消息的关联；地址移除临时令牌和签名，不上传 PDF。
3. 消息列表请求的 URL、方法、筛选及分页参数和脱敏响应，或分类／条目／分页的 DOM 样本。保留来源真实字段，核实消息 ID、类型、任务 ID、时间、结果链接及分页；移除 Cookie、Authorization、令牌和无关消息正文。
