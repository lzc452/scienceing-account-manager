# 第二期：订阅与 SCIHelp 结果通知

日期：2026-10-11。用户已授权开始第二期。依据：[一期需求与两期边界](2026-10-10-account-continuity-design.md)。本文确定实施边界及采集取证要求；尚未宣称科应采集接入或通知功能已经实现。

## 目标与闭环

使用者直接在科应创建订阅或 SCIHelp 申请，无需在账号平台重复登记。系统自动发现变化，持久记录，给关联使用者生成站内通知；使用者从通知指定领取原科应账号，打开对应结果入口。账号忙时保留通知并提示手动重试，不换号、不抢占账号。

继续采用 10 个普通科应账号供 20～30 人共享的模式。通知默认覆盖成功使用过该账号、当前仍启用的账号平台用户；不能根据当前租用者推断科应资源的创建者。通知体现“此共享账号有更新”，不标记为某个人的私有资源。

本期范围：订阅文献推送和 SCIHelp 完成结果的自动发现、后台检查、变化记录、去重、站内通知和结果入口。知识库和 AI 问答仍使用一期返回原账号的能力。不增加邮件、微信、PDF 托管、资源正文同步、预约领取或自动换号。

## 数据来源的实施选择

推荐使用已经核实的列表接口读取结果，后台定期检查配合使用期间的扩展读取。是否有可用的官方接口、接口是否能安全复用登录状态、是否会影响使用者会话，必须通过真实取证确认。

三种路径及取舍：

1. 官方或已核实的只读列表接口：分页和稳定标识容易验证，可直接核对账号身份及结果状态；当前仓库没有此能力的有效证据。
2. 已登录页面中的扩展采集：使用浏览器已有登录状态，可在使用期间补充发现变化，不向服务器传送 Cookie 或平台登录凭据；浏览器关闭后不能承担后台及时检查。
3. 服务器浏览器检查：可复用现有 Worker 编排模式，实现用户离线后的检查；若需要登录普通科应账号，必须先验证会话影响，且与领取、回收互斥。仅在账号空闲时登录意味着占用期间有检查延迟，不能宣称固定时限必达。

不能只依赖使用者手动访问某个页面触发同步，也不能用返回空数组的采集器或 Mock 数据宣称后台已接入。真实来源不能确认时，采集及其调度不能作为已完成交付。

## 采集取证与启用条件

对订阅推送列表和 SCIHelp 申请／结果列表分别取得证据：

- 实际入口地址、跳转域名，以及能确认当前科应账号身份的位置。
- 列表的稳定条目标识、分页规则、更新时间与空列表的判定方式。
- SCIHelp 待处理、完成、失败状态的真实字段或文案；订阅推送条目与订阅条件的对应关系。
- 结果入口使用的地址或资源标识，以及是否包含会过期的临时凭据。
- 检查与普通用户登录、管理员改密并发时的实际会话行为。

采集适配器必须由真实脱敏数据或 DOM 样本校验，不猜测科应内部接口地址、状态数字或 CSS 选择器。每次检查要验证账号身份，并在分页完整后才提交结果；登录失效、页面改版、超时或部分分页失败均记为检查失败，不能当成资源清空。

## 变化记录与通知规则

最小元数据包括科应账号 ID、资源类型、稳定来源标识、标题（来源存在时）、状态、来源更新时间、结果入口标识和检测时间。只记录通知所需信息，不存文献正文、PDF 文件、AI 对话、Cookie、密码或临时下载凭据。

首次完整扫描建立基线，既有内容不批量推送。后续检测：

- 新的订阅推送条目生成一次变化事件；同一条目重复扫描不再通知。
- SCIHelp 从已观察到的非完成状态变为完成时生成一次结果事件；重复完成状态不再通知。
- 来源未返回的条目不直接生成“删除”事件。本期不承诺删除同步。
- 变化事件和接收者记录在同一事务写入；以账号、资源稳定标识和变化版本去重。每个接收者对同一事件只能有一条通知。

账号停用后保留已有变化和通知，停止新检查；重新启用后继续检查。重复检查、服务重启和并发上报不得重复产生同一通知。通知和未读状态保存于数据库，退出登录不会丢失。

## 通知与原账号结果入口

登录用户可查看通知列表、未读数量和最近检测时间，标记自己的通知已读。服务端根据登录用户过滤，不允许通过通知 ID 查询或修改他人的通知。

通知显示共享账号编号、更新类型、检测时间及可用的简要标题。点击结果入口先走一期指定领取：已有目标租约时继续使用，持有其他账号时先归还，忙碌、回收、停用或异常时保持通知并明确失败。不得先打开可能属于另一科应账号的结果页。

结果入口经可信域名和路径验证后才交给扩展打开，账号 ID 必须贯穿全部消息链。旧扩展不支持结果入口能力时提示升级，不静默丢弃目标信息。具体入口由采集取证确定，不能把有时效的 PDF 下载链接作为永久入口。

## 检查时效与故障可见性

实现前须依据实际读取方式确定检查周期和账号占用时的处理。用户可看到最后成功检查时间及当前失败原因，不能把“没有检查成功”显示成“没有更新”。

一期的成功领取、活动续期、归还及自动改密优先。普通账号的后台登录检查需要互斥时，锁定、释放及超时恢复必须纳入领取事务和回收队列检查；不能复用“回收中”状态来冒充资源检查。

## 验收

- 直接在科应创建订阅或申请 SCIHelp，未在账号平台登记；正常检查后能自动发现新增推送或完成结果。
- 用户离线时仍能检查可检查的账号；忙碌或登录异常的延迟与失败在界面上可见。
- 基线、重复扫描、部分分页失败、服务重启、并发上报和同一结果反复出现不会产生错误或重复通知。
- 共享账号通知分配正确，用户不能访问他人的通知记录；列表中不包含平台凭据、全文或 PDF 内容。
- 点击通知准确返回原账号；目标忙碌或停用不会领取其他账号。入口过期或不可信时给出提示。
- 改密后继续检查同一个账号，资源身份保持一致；一期的并发领取和多标签页行为没有回归。

本期完成条件包含真实科应数据链路验收。仅完成数据表、通知页面或 Mock 不足以认定第二期完成。
