# 连续使用一期开发计划

依据：[一期需求](../specs/2026-10-10-account-continuity-design.md)。本计划由用户批准后执行。

## 实施顺序

1. 接口与领取：增加登录账号列表，聚合本人最近使用时间；领取接口增加可选 accountId，检查正整数、扩展版本、目标可用性、已有租约；全部租约检查与写入采用 BEGIN IMMEDIATE 事务。保留普通领取和现有证明校验。
2. 历史保护：已有租约记录的账号禁止删除或修改科应 username，允许修改展示 code；页面明确提示可使用禁用。同步管理员 Mock 和测试。
3. 页面与 Mock：首页显示“我用过的账号”和“指定账号领取”，显示状态、停用和最近使用时间；忙时允许刷新状态后重试，无自动换号。已持有目标账号可继续，持有其他账号先归还。Mock 保留租约历史独立于当前活动租约。
4. 扩展：网页、dashboard 内容脚本、后台和领取工具完整传递 accountId；将版本升至 1.4.0，同步服务端最新版本、下载包配置及文档。定向入口检查扩展版本。
5. 多标签页：后台消息和标签事件等待会话恢复；记录可信父标签的新标签，在网址可判定时仅为科应域名绑定；早到的内容脚本能获取稍后建立的绑定；父页关闭不影响已绑定子页，外部页面不参与续期，终态清理映射及续期计时器。内容脚本绑定完成后可靠启用真实操作监听。
6. 验证与交付：执行下列测试，记录真实科应环境待验证项目，提交功能并推送 origin 和 lan；两个远端分支 SHA 与本地 HEAD 一致才算 Git 交付完成。

## 接口约定

- `GET /api/accounts/mine`：登录后返回账号数组，包含 accountId/code/status/enabled/lastUsedAt/estimatedReleaseAt；启用账号均显示，停用账号仅显示本人使用过的记录。不返回 username、密码或其他使用者信息。
- `POST /api/leases`：accountId 可选，必须为正整数。缺失保留普通领取；非法值返回 400，不存在返回 404；已有其他活动租约、目标不可领取、扩展过旧返回 409，保持稳定错误 code 与用户可理解的 message。绝不因目标失败而查询其他可用账号。
- 扩展及页面调用保持现有请求 id、认证和一次性领取证明；扩展 1.4.0 以下不能使用定向领取。
- 不新增数据库表、后台采集任务、消息通知或依赖包。资源内容仍由科应提供。

## 自动化验证

- 后端：历史查询的登录、隔离、去重、排序、停用保留；领取的非法参数、准确目标、失败不回退、同账号重入、不同账号冲突、密码未配置、两人抢同账号及同人竞争；管理员删除和替换历史账号受阻，改展示编号和停用恢复正常。
- 网页：真实和 Mock 调用保持同一参数及错误语义，旧扩展入口禁用，新扩展定向参数完整传递。
- 扩展：领取请求体传递 accountId；后台恢复前到达的事件、网址延迟出现、新标签和父页关闭、内容脚本晚绑定、外部网站、租约归还及失效后停止续期。使用浏览器 API 测试桩验证后台事件，不把静态字符串检查当行为验证。
- 回归：共享包和后端构建、后端单元和接口测试、前端构建、扩展 manifest/check、相关部署打包检查、lint 和 typecheck。

## 发布核验与边界

基线、需求、计划和功能采用独立提交；每次交付都同步两个远端。不部署、不合并 main。第一期不保证原账号一直可用；第二期在第一期验收后基于真实页面和官方能力另行设计。

上线前人工使用真实科应账号核验：创建资源后归还改密，再指定原账号查看原有知识库、订阅、SCIHelp 申请和问答历史；逐一检查实际跳转域名、浏览器弹窗与新标签。没有真实科应认证时，只报告本地实现与自动化测试结果，不宣称完成外部平台验收。

实施结果与上线前待验收事项见 [2026-10-11 验收记录](../../account-continuity-validation-2026-10-11.md)。
