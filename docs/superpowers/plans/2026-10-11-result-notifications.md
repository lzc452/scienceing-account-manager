# 第二期开发计划

依据：[第二期需求及取证要求](../specs/2026-10-11-result-notifications-design.md)。起点为一期功能提交 `11e7cdd`；独立分支为 `codex/result-notifications`。

## 1. 先取得真实采集依据

读取订阅推送列表和 SCIHelp 申请／结果列表，记录脱敏字段、稳定标识、分页、账号身份、状态变化和结果入口。确认采用列表接口、扩展读取或浏览器检查的实际路径，并验证不会打断活动租约对应的用户会话。

产出：已校验的采集契约和最小真实测试样本。检查周期及账号占用时的行为据此明确写入需求。没有这些证据时，不编造上游接口或生产采集器，也不启动后台登录检查。

## 2. 变化与通知持久化

在现有迁移体系增加资源观察、变化事件和接收者状态。写入完整检查结果时，以资源稳定标识比较基线，在同一事务落变化及用户通知；接收者由该账号成功领取历史和用户启用状态自动生成。

验证：首次基线不刷历史通知、订阅新增及 SCIHelp 完成各通知一次、重复检查去重、并发写入一致、部分结果不覆盖完整基线、重启保留历史、停用和重新启用保留记录。

## 3. 接通实际采集与后台检查

在已验证的读取方式上实现采集器。复用现有 Worker 子进程编排、超时和日志脱敏；若使用扩展读取，账号必须由有效绑定租约决定，不能信任页面随意填写的账号 ID。

仅在验证确需互斥的后台登录路径中加入检查锁，并完整更新领取和回收调用链。故障记录检查失败及上次成功时间；登录失败、页面改版或分页不完整不能返回“无更新”。

验证：真实来源的分页、空列表和失败行为，用户在线及离线场景，检查与领取／改密并发，锁超时恢复及服务重启。

## 4. 通知页面与结果入口

增加登录用户的站内通知列表、未读数量和已读操作，同步真实 API 与 Mock。结果入口复用一期指定领取并传递已验证入口；扩展新增能力标记及版本门槛，防止旧版本丢弃目标参数。

验证：用户隔离、未读持久保留、目标忙碌手动重试且不换号、停用通知保留、旧扩展提示升级、入口可信域名检查，以及窄屏和键盘操作。

## 5. 回归与双远端交付

执行共享包、后端、网页、Worker 和扩展构建及相关行为测试；回归一期的历史、并发领取、管理员历史保护、多标签页及归还状态。记录真实科应验收结果与检查延迟，功能未接入真实来源时明确标记未完成。

需求、计划和功能各自独立提交，均推送 origin 与 lan，并核对两个远端分支 SHA 与本地 HEAD 相同。不提交密钥、账号会话、运行数据库、原始认证响应或助手记忆，不强制推送、不合并 main。

## 当前进度

已创建第二期分支并检查一期基线；需求与开发顺序已整理。尚未编写第二期功能代码、增加迁移或启用检查任务。真实列表采集契约及会话影响须先确认，后续步骤按依赖顺序推进。
